# Trust Atlas working instructions

- Project name: **Trust Atlas**. Subtitle: **From Hardware Security to Real-World Services**.
- Use English for project-authored documents, data descriptions, research briefs, comments, and interfaces. Add Korean only when useful or explicitly requested. Do not rewrite original source evidence merely to change its language.
- Read `CHARTER.md` as the source of truth for the project's mission and boundaries. TEE, confidential computing, and Private AI are the initial focus within hardware-rooted system security.
- Curate publicly available evidence into the knowledge graph. Keep future product/development proposals outside this repository. Evidence gaps request public sources, not new experiments on the researched systems; validation of the atlas itself is still required.
- Public availability alone does not establish scope fit. Admit hardware-rooted mechanisms and source-backed context for specific in-scope cases, not an independent application-domain catalogue. Preserve excluded records and IDs separately when narrowing scope; exclusion is not a negative security finding.
- Keep stable entity IDs and source provenance. Changes to wording, presentation, or taxonomy must not silently change the strength of a claim.
- Separate technical lineage, component use, conceptual comparison, attack relationships, and trust dependencies. Do not turn citations or visual proximity into inheritance.
- Scope security claims to assets, adversary capabilities, TCB, assumptions, exclusions, version, and evidence. Unknown is not false, absent, or zero.
- Muse provides bounded research candidates. Validate material claims against primary sources before accepting them. Do not create unrequested recurring research jobs.
- Run `python3 validate.py` after data edits. Check graph/data synchronization and affected interactions after visualization edits. Report incomplete research accurately.
- Keep copied source PDFs, scratch code, and temporary research outputs outside the deliverable directory. Do not publish until the user authorizes the actual release and its scope is concrete.
